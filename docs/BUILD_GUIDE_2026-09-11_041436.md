# Michi-Neko · 道猫 — BUILD GUIDE / Parallel Agent Checklist

**Date:** 2026-09-11
**Source:** `GAME_MASTER_REVIEW_2026-09-11.md` (merged master review)
**Purpose:** A comprehensive, execution-ready build checklist partitioned so that **multiple independent LLM/AI agents can work on different sections in parallel without editing the same files or blocking each other.**

---

## TL;DR — How to use this for parallel agents

- Each **Workstream** (WS) below owns a **disjoint set of source files** (see the ownership matrix). Two agents must **never** edit the same file at the same time.
- Every checklist item is a checkbox `- [ ]`. Agents mark items `- [x]` **only for files they exclusively own**.
- **Shared files** (`main.js`, `save.js`, `settings.js`, `sky.js`, `scent.js`, `index.html`) are each assigned to **one owner**. Any other workstream that needs a shared file must either (a) file its edit as a **cross-stream coordination note** for the owner to apply at merge, or (b) work on its own files only.
- Items that depend on another stream's output carry a **dependency note** (`depends-on: WS-A #1`) — do not start those until the dependency is done.
- Start with the **Priority 0** items (correctness & measurement) before content work.
- Respect the **"Explicitly NOT touching"** guardrails (Part 5 of the review) at all times.

### Status legend
- `- [ ]` Not started · `- [x]` Complete · `- [~]` In progress · `- [!]` Blocked (state the blocker) · `- [?]` Needs measurement/decision

### A1. Correctness & critical fixes (Priority 0)
- [x] **A1.1 — Fix adaptive-resolution stage 1 → 2 escalation (CRITICAL).** `perfStage` never promotes `1→2`, so pixel-ratio reduction is unreachable. Use sustained-low-performance timing: bad window → stage 0→1; still below target for 4–6 s → stage 1→2; at stage 2 lower pixel ratio gradually; require 10–20 s stable before restoring; add hysteresis to prevent oscillation. - [x] **A1.2 — WebGL context-loss recovery path.** Listen for `webglcontextlost`/`webglcontextrestored`; prevent default terminal failure; pause gameplay; show calm "The valley is resting…" screen; save current progress; attempt restore; offer "Reload and Continue" on failure. - [x] **A1.5 — Low↔High switching regression test.** Repeatedly switch Low↔High after the render-target reconstruction fix; verify no white screen and no context loss. (`main.js:415-444`)

## Explicitly NOT touching (guardrails — never modify)

- Painterly texture style, grade/vignette/grain/warmth look, cat rig & movement physics, day/night/weather lighting, gameplay logic foundations, generative music identity, audio identity.
- Do **not** add 512px textures or heavy downloads — 256px procedural canvas textures are ideal (`textures.js`).
- Preserve the **"no fail states, no combat, no timers"** pillar.
- Avoid expanding the map too early — a smaller, deeply reactive Kyoto valley beats a large set of attractive-but-static districts.
- Avoid mandatory chase/runner sequences as the main escalation — free spatial exploration is the identity; set pieces should be rare changes of pace.

## Final recommendation (design north star)

> "I wonder what happens if I sit here during rain," not merely "Where is the next marker?"

The strongest Michi-Neko: moving is enjoyable; remaining still is rewarding; weather changes behavior; NPCs have lives of their own; the player behaves expressively like a cat; progress is remembered without being constantly scored; the small world keeps revealing new details; performance quietly adapts unnoticed.
