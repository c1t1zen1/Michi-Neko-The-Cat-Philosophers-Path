## Deferred (classic), with reasons
- `summit-clouds`: the sky kit (`v-sky`) is not merged, so there is no cloud kit to reuse; it stays classic. Layout already carries every lobe (drawn from the summit stream); a kit would need `summitClouds` records through `footprint.anchors` with the classic shape (`{ mesh, material, storm, speed, minX, maxX }`).
- `blender-roofscape`: the optional GLB with a fallback (media, not a kit asset), as the brief says.

## Reuse
- `pagoda`: `buildPagoda` (read-only import from `src/kit/pagoda/build.js`) with preset `yasaka`, height 13.5 m by default (46 m real; the summit's scale), tier = the asset's tier (the game builds it at far tier: `layout.x,z` is past 80 m).
- `ranges`: `ridgeRingGeometry` (read-only import) builds each horizon range as a polar height-field ring; only the arc |bearing| < 1.15 rad of +z is kept.
- The summit's own height function: `src/kit/vista/ground.js` runs `terrainMethods.terrainHeightAt` (from `src/summit/terrain.js`, read-only) on a plain object, since `terrainHeightAt` reads only pure helpers. That keeps `vistaGroundHeight` and every landform height untouched (the kit never writes terrain).

## Behaviour notes
- Window lights come on in a wave from the river: a per-point threshold in the point shader read against the opacity the summit already drives (no clock of its own).
- The Ferris wheel turns on its own `update()` (0.035 rad/s); gondolas stay level.
- The summit builds these layouts at x,z near 0 (city, bay, harbour, horizon, vista-terrain: hero on high / mid on medium) and the pagoda, bridge and wheel at far tier (their layout positions are past 80 m): the kit's far tier is what the player sees for those three.
- Preview quality: classic builds 430 houses and 160 garden trees when `game.summitPreview` is set (`this.previewQuality`); a kit builder cannot see that flag, so the preview shows the full game density (920 / 360). The game itself is unchanged.
