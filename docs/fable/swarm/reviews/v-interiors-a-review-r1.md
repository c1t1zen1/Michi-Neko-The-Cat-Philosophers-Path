### Named-risk verdicts
1. **BUDGET_EXCEPTIONS['tea-interior']**: Treating the room as one asset is right. tea-interior is the inventory id for the whole room, the ten parts already exist as separate ids and are individually within the per-asset caps (contract run: only tea-interior fails), and budgets.js:46-48 itself names "a whole machiya, the pagoda" as the intended exception class. Splitting would just re-create the ten standalone ids. Numbers are acceptable but padded: hero buildMs 12 vs 6.4 measured and mid buildMs 8 vs 4.1 (about 2x headroom where 15-25 percent is the norm elsewhere); mesh/material/triangle caps (34/12, 9,500 vs 7,753, 3,000 vs 2,436) are fine. The far tier (2,436 tris, 23 meshes, 10 materials) is barely reduced from mid (7,753) and is 2.4x the standard 1,000; moot because the room is only ever seen from inside, but recorded. Hero triangle cap stays at 25k (not requested to raise). Suggest tightening buildMs to hero 9 / mid 6 / far 4; not blocking. See Minor 4.
2. **main.js skips assets.update while inside**: Classic neutrality holds: the handoff patches change nothing for classic (`CLASSIC_ASSETS.update()` is a no-op, runtime.js:526; `this.interior.assets` is always a scoped view, interior.js:65; `view.update` only walks the interior's instances, runtime.js:347). Correctness: the main.js patch (handoff 4) is safe and should be applied; without it the freeze is user-visible. L6 noon (tea-interior-12-modular.jpg vs -classic.jpg): the classic andon is lit, the modular andon is dark because `lanternOn` was false at the entry frame, while the "Andon Glow Light" point light is on next to it; at 22 h it is lit. Classic's andon and shoji are constant (interior.js:17,22), so this is a parity regression in daytime, and a stay across dusk never updates. The report treats patch 4 as "recommended" and marks AAA-5 satisfied; it is not satisfied at noon without it. See Important 1.
3. **Room lights handed to manager on first update** (tea.js:88-93): `hooked` guards double registration; assets.update does run for the interior's instances while outside (runtime.js:347, main.js:1509), and the interior is built once in Game (main.js:242, no rebuild, no dispose path, merged instances never `setTier` so no re-tier rebuild), so I found no context-loss/re-entry leak: lights are plain PointLights parented to the instance root, removed with the group on dispose; `gi.roomLights` would hold stale refs only after a dispose that never happens in the game. Fragilities: kit code reaches `window.game.interior` (a kit file importing game state by global, tea.js:88), works only if one outside update runs before the first entry, and silently leaves the room unlit (lights stay `visible=false`) otherwise. Handoff 2's `setLightsActive` loop is the clean fix and is correct (`_lightsActive` guard is fine); make it required and delete the hook. See Important 2.
4. **Knockables bodies/names/anchors**: bodies and anchors preserved (above). Names differ: classic meshes are named "Table Knick-knack N" (interior.js:239-254) and the golden keys on those names; kit meshes get `asset:knockables/<part>`. No code looks the names up (grep), but `tools/golden/systems_classic.json` keys include the classic names, so a modular `--systems` diff is expected, which the waiver covers. Visual bug in the fix: the cup is placed at (-0.55,-0.45) and the teapot at (-0.45, 0.49, -0.45) (teaware default z -0.25 plus table z -0.2), centre distance 0.10 m versus radii 0.09 + 0.058: they interpenetrate (knockables-12-modular.jpg shows cup and pot touching). See Minor 1.
