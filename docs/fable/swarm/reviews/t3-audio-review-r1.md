# t3-audio review r1 — verdict: APPROVE with notes (T3.3 sink gap = integrator item)

Constraints: no kit file imports src/audio.js (only a comment mentions it); sound via env.audio; classic: env.audio is null/silent, runtime default no-sink. dawCAT tests reported 251/0 (not re-run by me; diff is limited to 5 dawCAT files, all lane-owned, no WIP).

1. Is env.audio a no-op in the game today? YES. main.js assetEnv() sets env.audio = this.assets.audio, but no setSink is called, so play() returns false. No family calls it either (garden's clack still only calls onClack). T3.3's "design + patches" is met; audible result is not. Minimal classic-neutral install, one block in main.js after `this.assets` is built (line ~213): the handoff's `this.assets.audio?.setSink(...)` mapping shrine.bell.ring->audio.playBell(), nest.settle->audio.playPurr(), others silent. Classic-neutral because classic builds no kit instances that call it. Recommend the lane (or integrator) apply it only together with the first family call-site, else it is dead code. Not a blocker; lane was granted main.js so could have added it, but an unreachable sink is harmless to defer. Note the dawCAT-pack path (playSfx) is described only in prose; nothing installs it.
2. API safety: play() is guarded (no sink, unknown event, try/catch around sink) so it cannot throw. Locked autoplay: playBell/playPurr check `initialized` (AudioManager.init on gesture); a suspended ctx would just schedule; no crash. The hook itself knows nothing about mute, locked state, or reduce-motion/comfort — those must live in the sink (src/audio.js buses honour master/sfx volume). Fine, but the handoff should say the sink owns gating. Allocation: play(event, opts) does `opts || {}` (alloc only if caller passes none) and callers' `{pos, gain}` literals allocate per call; the Set lookup is cheap. All listed triggers are edge/cooldown-based (clack 0.6 s, chime 0.8 s, noren 1 s), so no per-frame call is specified; families must not call it unconditionally each frame — add that to the contract. Minor: the sink gets no throttle for lantern.kindle bursts (handoff suggests 0.15 s throttle in the sink; not implemented).
3. dawCAT: staged files are only the lane's. GAME_AUDIO_CATALOG.json is a generated artifact (tools/catalog-game.mjs, `npm run library:catalog`) but is NOT written by it with kit data: it only holds sha256 of src/audio.js, hidden_places.js, music.js plus 28 entries. The md kit section is appended by the generator (kitCatalogMarkdown), so md regeneration is reproducible. JSON staleness is pre-existing: src/hidden_places.js sha no longer matches (audio.js, music.js match), so verify-library's "Source audit" check would already fail independent of this lane. Not a lane defect; regenerating would churn unrelated lines (the lane correctly reverted that). Flag to the operator as separate chore.
4. Per-family patches: only garden is verifiable. The cited site exists (src/kit/garden/build.js:133, in update with `env` presumably in scope; the update signature should be confirmed by the garden owner — `env` is in scope per the runtime contract `update(dt,t,env)`). Patch is "add a line", not a diff, and is exact enough. Lanterns, shrine, water, noren, keepsakes, nest are prose descriptions with no line numbers (shrine and water families are not in src/kit at HEAD; ringBell does not exist there). Therefore these are guidance, not exact applicable patches; acceptable for unmerged families but integrator must treat them as to-do. Keepsake/nest note correctly says not to double-play.

Blockers: none. Required follow-ups (integrator): install sink with first wired family; state in contract that sink owns mute/lock/comfort gating and that play() must be edge-triggered, never per-frame.
